# Support policy

## Supported environment

Support covers the latest published Realistic Trading Overhaul build for the exact Minecraft and
NeoForge lines listed in the [supported versions page](wiki/Supported-Versions.md).

Before reporting:

- reproduce problems on the newest RTO release;
- install RTO on both the client and dedicated server;
- remove unsupported coremods or binary patches before claiming an RTO incompatibility; and
- keep the original crash report and `latest.log`.

## Where to ask

- Bugs, crashes, and compatibility failures: GitHub Issues using the matching form.
- Setup questions and gameplay help: GitHub Discussions, Q&A.
- Feature ideas: GitHub Discussions, Ideas.
- Security vulnerabilities: GitHub private vulnerability reporting.

CurseForge comments are intentionally disabled so reports are not split across two trackers.

## Response expectations

Reports are triaged best-effort. A complete reproduction, logs, and an exact mod list receive
priority. Duplicate, unsupported-version, log-free, or non-reproducible reports may be closed with a
request for more information.

## How a report moves

Labels show where a report stands:

| Label | Meaning |
| --- | --- |
| `needs-triage` | New; not reviewed yet |
| `needs-info` | Waiting for you to add logs, versions, or steps. Reports left here without a reply may be closed |
| `confirmed` | Reproduced and accepted |
| `tracked` | Being worked on by the development team. Development is private, so progress is not posted here |
| `fixed` | Fixed in a released build; the closing comment names the version |
| `duplicate`, `out-of-scope`, `wontfix` | Closed without a change |

Documentation errors use the **Documentation correction** form.

Do not post access tokens, account data, server addresses intended to be private, or personal
information in logs. Redact those values without removing the exception or stack trace.
